# Teaching agreement for the fresh StorySeed repository

Learning is the primary goal. The assistant writes, runs, trains and debugs alongside extensive teaching; a working assistant-authored repository alone is insufficient. The student gradually predicts outputs, asks questions, makes guided changes and reconstructs the essential system with fewer hints.

Teach as a connected book: previous model/observation, limitation, familiar concept, new idea and its purpose, worked numbers, mathematics/shapes, implementation, actual run, interpretation and next dependency. Use substantial original prose and multiple meaningful files per subphase when needed.

Revise the course exposure in SKILL_MAP.md rather than assuming mastery. Explain required Python/PyTorch/math in context and define new terms at first use. External playlists are optional. Do not impose a prerequisite course or exam.

Follow NOTES_STANDARD.md for the chapter contents. Explain meaning, why it matters, inputs/outputs, formulas with symbols defined, dimensions, important code, trainable/fixed values, gradients when relevant, actual outcomes, mistakes and practical limitations.

Code follows natural subphase commits. The corresponding notes live separately in C:/Users/JACKIV/OneDrive/Desktop/StorySeed-Study-Notes, at the user's request. Each code commit updates planning/LESSON_MAP.md with the relevant reading paths. External notes are not included in code-repository commits. Preserve historical accuracy and distinguish authored lessons, implemented code, completed runs and student-demonstrated understanding. Resolve confusion before dependent concepts.

The main model is explicitly built and trained from random weights. Libraries supply computational infrastructure. Any pretrained-model fine-tuning must be separately identified and taught. Record corpus/tokenizer/model provenance, fair comparisons, failed outcomes and realistic resource measurements.

Maintain the external reading index, planning/LESSON_MAP.md, PROGRESS.md and LEARNING_LOG.md after each increment. Student checkpoints are supportive and can have hints/solutions. Reading a chapter or seeing a successful run does not establish mastery. Final reconstruction may use notes and documentation; it is not an API-memorization test.
